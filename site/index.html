workflow

One flow for new work and maintenance.

Chạy keeps old feature contracts updated instead of creating competing docs. When scope changes, graph, context, work note and handoff move together.

CASE A Continue existing feature

A new AI session reads the right feature context and continues from the handoff.

ai_handoff.json
CASE B Add or change feature

The human sees the flow, sequence, API/code relation and code targets before AI edits.

cr go "Task"
CASE C Verify AI edit

The patch is checked against the feature boundary and old feature scope before handoff.

cr verify

guardrails

The AI edits code. The contract keeps it honest.

The runtime is intentionally small: one folder for machine state, one folder for human-readable structure, and a strict selected-file boundary.

No stale scopeWhen a goal narrows, old migration or API targets are dropped unless the new intent still needs them.
No generic keyword matchingWords like user or admin are not enough to map a task into an existing feature.
Readable artifactsFeature flow lives in Markdown. Diagrams live in PlantUML. JSON stays in chay-memory.

cr verify

quickstart

Built for production repos, not demo scaffolds.

Use explicit files when the first feature is sensitive. After that, Chạy can maintain the existing contract and keep follow-up work on the same feature id.
